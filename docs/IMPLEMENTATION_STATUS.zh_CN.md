## 6. 发布与升级口径(v1.1 起,已拍板)

- **存档兼容**:固件升级走 app-only 烧录(`idf.py -p COMx flash` 或
  `esptool write_flash 0x10000 FoloToy-AI-Passport.bin`),NVS 存档保留;
  v1/v2/v3 存档由 `dr_state_load` 按实际长度验 CRC 后逐版迁移到 v4
  (当前 DR_SAVE_VERSION=4;职业重映射,老档 builder=帮忙+森林兜底)。
- **整片镜像会清档**:`-full.bin` 从 0x0 写入,NVS(0x9000)被 0xFF 覆盖
  ——只用于首装/救砖。**发布同时给两个产物**,说明写明"老玩家升级用
  app.bin"。
- **浏览器烧录=全量=清档(2026-10-05 取证)**:官方社区发布管线只收
  "单一合并镜像从 0x0 写入"(merge-bin 在 0x9000~0x10000 用 0xFF 填充,
  必然覆盖 NVS)。**保档升级目前仅 COM 口 app-only 路径**。候选解法:
  ①自建烧录页用 ESP Web Tools manifest 分段写(只写 0x8000 分区表 +
  0x10000 app,不碰 NVS);②游戏内存档码导出/导入(原版本有 save string,
  对全量渠道免疫,烧录前把码抄走即可;候选排 M7,见 §0)。
- **flash 尺寸已定**:sdkconfig 2MB→8MB(2026-09-30,与真机物理 flash 一致);
  分区表为默认单 factory 布局:nvs@0x9000(24KB)+phy@0xF000(4KB)+
  factory app@0x10000(**1MB**)。0x110000 以上 **6.9MB 完全未分配**。
- **app 1019KB 构成**(2026-10-04 map/对象实测;M6 切片一起余量 10%→3%):
